OrcAI can be run as a local Docker Compose stack or as manually managed Bun app and worker processes connected to external services.

For most self-hosting experiments, start with [Docker Compose quickstart](/docs/self-hosting/quickstart-compose). Use [manual setup](/docs/self-hosting/manual-setup) when you need to manage PostgreSQL, Valkey, Qdrant, SpiceDB, S3-compatible storage, and workers yourself.

<Callout title="Not production hardened" type="warn">
	These pages document what the repository can run today. They are not yet a complete production operations guide.
</Callout>

## Required infrastructure

- PostgreSQL
- Valkey
- S3-compatible object storage
- Qdrant
- SpiceDB
- An OpenAI-compatible endpoint for embeddings
- Background workers

## Caveats

- `docker-compose.local.yaml` is a development override, not a production deployment manifest.
- Assets cannot be indexed until the embedding endpoint, model and dimensions are set. Changing them on an existing instance means recreating the Qdrant collection and preparing the assets again.
