Use manual setup when you want to run OrcAI directly on a host instead of using the full Compose stack.

## Prerequisites

- Bun `>=1.3.10`
- PostgreSQL
- Valkey
- Qdrant
- SpiceDB
- S3-compatible object storage
- OpenAI-compatible endpoint for embeddings
- Tesseract with `eng` and `deu` language packs if workers run on the host
- Optional SMTP server

## Install Dependencies

```bash title="Repository root"
cp .env.example .env
bun install --frozen-lockfile
```

Edit `.env` before starting the app. See [Configuration](/docs/self-hosting/configuration) for required variables.

## Initialise Data Stores

Apply the database migrations and the SpiceDB schema:

```bash title="Repository root"
bun run stack migrate
```

Package scripts do not read the root `.env`, so run them through `bun run stack`, which loads it. `bun run stack exec -- <command>` does the same for any other command.

## Start Development Processes

Start the app:

```bash title="Terminal 1"
bun run dev
```

Start background workers in a separate terminal:

```bash title="Terminal 2"
bun run workers:dev
```

The app is available at:

```text
http://localhost:3000
```

On a fresh database, complete initial instance setup at `http://localhost:3000/init`, as described in [Initialise the instance](/docs/self-hosting/quickstart-compose#initialise-the-instance-step).

## Production Commands

Build and start the app:

```bash title="App process"
bun run build
bun run stack exec -- bun run start
```

Start workers:

```bash title="Worker process"
bun run stack exec -- bun run workers:start
```

## Host OCR Notes

OCR-backed asset preparation runs in the worker process. When workers run outside Docker, install Tesseract and the configured language packs. Use `KREUZBERG_OCR_LANGUAGE=eng+deu` only where both packs are installed.
