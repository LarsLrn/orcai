title: Services
description: Runtime services used by OrcAI.
---

OrcAI is a multi-service application. The app and workers are separate processes that share the same backing services.

## Service Map

| Service | Role | Required for |
| --- | --- | --- |
| App | UI, authentication, API routes, workflows | All user-facing use |
| Workers | Background jobs and scheduled maintenance | Content processing and quotas |
| PostgreSQL | Relational application data | Core persistence |
| Valkey | Cache and coordination | Runtime support |
| SeaweedFS/S3 | Uploaded and processed files | Content library |
| Qdrant | Vector indexes | Retrieval |
| SpiceDB | Authorization relationships | Access control |
| AI endpoint | Embeddings and chat model calls | Chat and ingestion |

## App

The main app is a Bun/TanStack Start application. It serves the user interface, authentication, oRPC API routes, and application workflows. It also works the data export queue, because building an export's chat transcripts needs the app's own code.

In Docker Compose, the service name is `app`.

## Web (Docs)

The repository Compose stack also includes a `web` service for the documentation website. The app reads the docs from it, through `WEB_INTERNAL_URL`, when the OrcAI Assistant answers questions about OrcAI.

## Workers

Workers run background jobs for asset processing, vectorization, releasing quota reservations of replies that never ended, and quota period rollover. Workers must be running for uploaded content to become searchable. They also create the data export queues, which the app works.

## PostgreSQL

PostgreSQL stores application data. The Compose stack uses the `pgvector/pgvector:0.8.7-pg17` image, although retrieval vectors are stored in Qdrant.

## Valkey

Valkey is used as a cache and supporting infrastructure service by the app. Workers do not use it.

## SeaweedFS Or S3-Compatible Storage

Uploaded files and processed artifacts are stored in S3-compatible object storage. Compose runs SeaweedFS in single-container mode, which creates the required buckets on startup and takes its credentials from `S3_ACCESS_KEY` and `S3_SECRET_KEY`.

Installations that ran the earlier MinIO service start with an empty `seaweedfs_data` volume. Copy the `uploads` and `processed-files` buckets from MinIO with an S3 tool such as `rclone sync` before switching, keeping the object keys unchanged, and keep the old `minio_data` volume until the copy is verified.

## Qdrant

Qdrant stores vector indexes for retrieval. The embedding dimensions in Qdrant must match `EMBEDDING_DIMENSIONS`.

## SpiceDB

SpiceDB backs authorization checks. The repository includes schema files under `packages/spice-db/src/schema` and commands to apply or inspect the schema.

## AI Endpoint

OrcAI uses an OpenAI-compatible model endpoint for embeddings and model calls. The configured endpoint must expose the embedding model and general-purpose model selected in environment variables.

Custom embedding and image-processing model definitions are only supported in self-hosted deployments.

## Document Processing

Kreuzberg handles document extraction. OCR requires Tesseract in the worker environment.
