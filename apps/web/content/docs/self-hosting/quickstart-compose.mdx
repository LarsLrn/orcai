Use the Compose quickstart when you want a runnable local stack outside the devcontainer.

## Prerequisites

- Docker with Docker Compose.
- An OpenAI-compatible endpoint that serves your embedding model. Chats use the providers an admin adds in the app.
- A local `.env` file based on `.env.example`.
- Values for `EMBEDDING_MODEL` and `EMBEDDING_DIMENSIONS`.
- Secrets for auth/encryption (`BETTER_AUTH_SECRET`, `ENCRYPTION_KEY`) for anything beyond throwaway local testing.

## Start The Stack

### Create The Environment File [step]

If you do not have a local `.env` yet, create one from the example:

```bash title="Repository root"
cp .env.example .env
```

Edit `.env` before starting the stack. At minimum, set the AI variables below.

### Run Compose [step]

From the repository root:

```bash title="Repository root"
docker compose -f docker-compose.yaml -f docker-compose.local.yaml up -d --build
```

The app is published on:

```text
http://localhost:3000
```

### Initialise the instance [step]

On a fresh database, open `http://localhost:3000/init`. The sign-in page sends you there until the instance is initialised. The form creates the first account, which is the instance admin, and the first organisation with that account as its admin. It asks for **Organisation name**, **Organisation slug**, **Admin name**, **Admin email**, **Password** and **Confirm password**, and for consent to the privacy policy and terms of use. Once you choose **Initialise instance**, the page is no longer available, and every later account comes from an invitation (see [Creating accounts](/docs/self-hosting/operations#creating-accounts)).

Chats need a provider and models, which the new admin adds in the app. [Organisation setup](/docs/using-orcai/organisation-setup) walks through it.

## Services And Ports

The local override publishes:

| Service | Default port | Purpose |
| --- | ---: | --- |
| OrcAI app | `3000` | Main web application |
| OrcAI docs | `3001` | Documentation site, which the Assistant reads |
| PostgreSQL | `5432` | Application database |
| Valkey | `6379` | Cache and coordination |
| SeaweedFS S3 API | `8333` | S3-compatible object storage |
| Qdrant HTTP | `6333` | Vector database HTTP API |
| Qdrant gRPC | `6334` | Vector database gRPC API |
| SpiceDB gRPC | `50051` | Authorisation service |
| SpiceDB HTTP | `8080` | SpiceDB HTTP API |
| SpiceDB metrics | `9090` | SpiceDB metrics |
| SpiceDB PostgreSQL | `5431` | SpiceDB backing database |

Most ports can be overridden with environment variables such as `APP_PORT`, `WEB_PORT`, `POSTGRES_PORT`, `S3_PORT`, and `QDRANT_HTTP_PORT`.

## Required AI Variables

The local override provides development placeholders for some secrets, but these embedding variables need real values, because assets cannot be indexed or searched without them:

```bash title=".env"
OPENAI_COMPATIBLE_BASE_URL="https://your-ai-provider.example/v1"
OPENAI_COMPATIBLE_API_KEY="replace-with-openai-compatible-api-key"
EMBEDDING_MODEL="baai/bge-m3"
EMBEDDING_DIMENSIONS=1024
```

<Callout title="Keep embeddings stable" type="warn">
	Keep `EMBEDDING_MODEL` and `EMBEDDING_DIMENSIONS` stable after indexing data. Changing them requires recreating the Qdrant collection and preparing assets again.
</Callout>

## Stop The Stack

```bash title="Repository root"
docker compose -f docker-compose.yaml -f docker-compose.local.yaml down
```

Add `-v` only if you intentionally want to remove local volumes and lose stored database, object storage, Qdrant, and SpiceDB data.

## Production-Like Notes

- The local override injects development defaults for several values; treat those as non-production.
- Without the local override, `docker-compose.yaml` publishes no ports. [Public URLs](/docs/self-hosting/configuration#public-urls) lists what browsers must reach.
- Keep `EMBEDDING_MODEL` and `EMBEDDING_DIMENSIONS` stable after indexing data.

## What Compose Initialises

The Compose stack includes one-shot services for:

- Application database migrations.
- SpiceDB schema migration.

SeaweedFS creates the `uploads` and `processed-files` buckets itself on startup.
