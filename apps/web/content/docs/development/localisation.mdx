---
title: Localisation
description: How interface copy is translated, how messages are named, and how tests find translated text.
---

The app is translated with [Paraglide](https://inlang.com/m/gerre34r/library-inlang-paraglideJs). Copy lives in `apps/app/messages/<locale>.json`, one file per locale, and compiles to typed message functions under `apps/app/src/paraglide`. That output is generated, not committed; `bun run ci` compiles it before the type check, and the Vite plugin does the same during `dev` and `build`.

## Locale Resolution

The locale is not in the URL. Paraglide resolves it from the `PARAGLIDE_LOCALE` cookie, then the browser's `Accept-Language`, then falls back to the base locale `en`. The header's language switcher sets the cookie and reloads. A preference stored on the user account is planned to sit ahead of the cookie once it exists.

Locales: `en` (base, British spelling) and `de`.

## Messages

Every user-facing string in `apps/app/src` comes from a message function:

```tsx
import { m } from "@/paraglide/messages";

<Button>{m.chat_composer_send_button()}</Button>
```

Message functions are plain functions, so hooks, utilities, loaders, and server functions call them the same way. On the server the Paraglide middleware in `apps/app/src/server.ts` scopes the locale to the request.

Keys are flat, lower snake case, and named after where the text lives, not after what it says:

```
<area>_<component or screen>_<element>[_<qualifier>]

chat_composer_send_button
library_bot_card_share_action
settings_members_invite_dialog_title
```

A key never encodes its English text, so rewording the copy leaves the key alone. When the surrounding component is renamed, rename the key with it. Interpolation uses `{name}` placeholders, plural and other variants use Paraglide's variant syntax in the message file, and copy with inline links or emphasis is split into separate messages around the marked-up part. Dates, numbers, and relative times go through `Intl` with the active locale from `getLocale()`.

Out of scope for translation: content that users author, such as bot names, descriptions, documents, and organisation copy.

## German

German uses the formal "Sie". Product terms that stay English in German copy: Bot, Chat, Prompt, Dashboard. Terms that are translated:

| English | German |
| --- | --- |
| Library | Bibliothek |
| Workspace | Arbeitsbereich |
| Organisation | Organisation |
| Group | Gruppe |
| Member | Mitglied |
| Source | Quelle |
| Block | Block |

`bun run machine-translate` fills gaps in the non-base locales from `en.json`; review its output before committing.

## Tests

Unit tests never depend on copy. End-to-end specs locate elements by role and accessible name, and take the name from the message catalogue rather than repeating the English:

```ts
import { message } from "../../fixtures/messages";

page.getByRole("button", { name: message("chat_composer_send_button") });
```

The helper reads `apps/app/messages/en.json` directly, so it needs no compile step. It resolves plain strings and `{placeholder}` interpolation; a message with variants throws, and the spec targets the rendered text another way. Test ids are for containers that have no accessible name, never for anything a message names.
