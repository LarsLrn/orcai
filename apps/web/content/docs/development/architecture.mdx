## Runtime Components

- React 19 and TanStack Start power the user interface and server runtime.
- TanStack Router, Query, and Form are used for client routing and data workflows.
- oRPC defines typed backend contracts.
- Better Auth handles authentication.
- Drizzle ORM manages PostgreSQL access and migrations.
- pg-boss coordinates background jobs.
- Qdrant stores vector indexes.
- SpiceDB handles authorization relationships and permission checks.
- S3-compatible storage stores uploaded and processed files.
- Kreuzberg and Tesseract handle document extraction and OCR.
- The AI SDK talks to an OpenAI-compatible model endpoint.

## Content Processing Flow

1. A user uploads material through the app.
2. The app stores files in S3-compatible object storage.
3. The app creates background jobs.
4. Workers extract content from the uploaded material.
5. Workers create processed artifacts and metadata.
6. Workers generate embeddings using the configured model endpoint.
7. Workers write vector data to Qdrant.
8. Chat tools query Qdrant and retrieve relevant content for model calls.

## Authorization Flow

The app stores domain records in PostgreSQL and uses SpiceDB for relationship-based authorization. Permission middleware checks whether a user can access or mutate a resource before executing protected operations.

### Read Consistency

Authorization reads are near real-time by default: SpiceDB answers them with `minimizeLatency`, which can miss a permission change made moments earlier. A request that writes authorization returns the resulting zedToken in the response `meta` and sets a `zed_token` cookie for 60 seconds, so the browser's following reads are at least as fresh as that write.

The sign-up response carries the same cookie for the membership it grants, so a new account's first reads already see it.

API consumers outside the browser can send the token back in the `X-Zed-Token` header, and some procedures also accept it as a `zedToken` input to pin the freshness of a single call.

A response without `meta.zedToken` means the request wrote nothing to SpiceDB inline; the write is queued and applied shortly after, so a read issued immediately may still see the previous state.

## AI Flow

Chat generation uses configured providers and models. Retrieval tools can search knowledge-base content, list documents, and fetch pages or chunks before the assistant response is generated.

Image-related processing can use `GENERAL_MODEL` to describe images during asset processing.

## Observability

Umami analytics is optional. OpenTelemetry export is on when `OTEL_EXPORTER_OTLP_ENDPOINT` is set; `@orcai/observability` then builds one resource for traces, logs and metrics from `OTEL_RESOURCE_ATTRIBUTES` and the service name and version, and registers the tracer and meter providers globally for libraries that use the OpenTelemetry API.

- Traces: the app opens one server span per request named `<method> <route template>` (RPC requests carry the procedure path, auth requests only the template); oRPC, Better Auth, Effect SQL, pg-boss `send`, AI SDK and HTTP client spans nest under it. A worker's `process <queue>` span continues the trace of the request that queued the job; batches of several jobs link to each producer instead. Effects started from promise-based code join the active span through `withActiveSpan` in `@orcai/observability` and `runPromise` in `apps/app/src/lib/effect/runtime.ts`.
- Logs: Effect log records are exported with the trace and span ids of the fiber that wrote them.
- Metrics: pg-boss messaging metrics (`messaging.*`, `pgboss.queue.jobs`) and the HTTP client duration, exported every minute.
- AI calls record model, token usage and the organisation, chat, provider and model ids, never prompt or response content.
