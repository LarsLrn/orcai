Bots are reusable AI configurations that can be selected at chat start. They are authored in the Library (`/app/hub`) and combine behaviour, retrieval context, and sharing settings.

## Library Sections

The Library (`/app/hub`) has five tabs:

- All (`/app/hub`)
- Bots (`/app/hub/bots`)
- Behaviour (`/app/hub/behaviour`)
- Repositories (`/app/hub/repositories`)
- Assets (`/app/hub/assets`), described in [Content Library](/docs/using-orcai/content-library)

The sidebar lists the same sections under Library. Each needs the organisation's `read` permission, which every role has.

## Core Concepts

- Bots: named AI setups users can select when starting a chat.
- Blocks: reusable building blocks used by bots and chats.
- Behaviour blocks: AI behaviour blocks, whose system prompt sets the bot's role, tone and limits.
- Repository blocks: database blocks that package assets with retrieval settings.
- Assets: uploaded files that can be attached to repository blocks and chats.

A bot fixes no model and no quota pool. Each chat runs on the provider and model chosen in that chat, and usage is charged to the quota pool that covers the chatting person and that provider.

## Bot Lifecycle

Bots (`/app/hub/bots`) have draft and published states, shown as two sections:

- **Published** lists the bots ready to use in chats that you can read.
- **Your drafts** lists bots not yet published, with **Edit draft** and **Delete draft** where your role on the bot allows them.

**Create bot** appears for roles with `create_bot` (admins, managers and members).

A bot is private until it is shared. Publishing does not share it: a published bot is usable only by the people and groups it was granted to, or by everyone when it is public. See [Access Control](/docs/using-orcai/access-control#resource-sharing).

## The Bot Page

A bot's page (`/app/hub/bots/<bot id>`) shows its behaviour and repositories. Depending on your role on the bot it offers:

- **Start chat**, for anyone who can use the bot
- **Access & groups**, which opens the access dialog
- **Edit bot**, which opens the editor
- **Delete bot**

## Creating Or Editing A Bot

**Create bot** opens the editor at `/app/hub/bots/add`. The first save creates a draft and moves the editor to `/app/hub/bots/<bot id>/setup`, the same place **Edit bot** opens. The later steps unlock after that first save, and moving between steps saves your changes.

The bot editor is a guided wizard with five steps:

### Bot Basics [step]

Name the bot and give it a short description and a longer bot description for teammates who maintain it.

### AI Behaviour [step]

Write a new AI behaviour, start from an example, or choose **Use existing AI behaviour**. The system prompt has no default.

Below the behaviour block, the Features section lists the built-in features the bot can enable. See [Features](#features).

### Repositories [step]

Attach ready repository blocks that provide retrieval context. Repositories are optional: create one, choose **Add existing repository**, or attach none.

### Sharing And Access [step]

Configure visibility, groups, and direct grants for the intended audience. Giving someone edit or manage on the bot also offers edit on its blocks, for the blocks you can share.

### Review And Publish [step]

Review the publishing checks, then choose **Save draft** to keep the bot as a draft or **Publish bot**. Publishing asks for confirmation and summarises who gains access, and that the bot fixes neither a provider and model nor a quota pool.

The editor supports:

- Creating new blocks inline
- Linking existing blocks from block libraries; linked blocks you cannot edit appear read-only
- Persisting linked blocks while progressing
- Publishing when validation rules pass

## Features

Features are built-in behaviours that work alongside the template and repositories. They belong to the bot, not to its behaviour block: switching the template keeps the bot's features, and the same template can be used with or without them. Each feature is a switch in the Features section of the AI Behaviour step and is saved with the bot.

Available features:

- Generative UI: lets the model show structured results, such as checklists, in its answer. It is on by default for new bots. See [Generative UI](/docs/using-orcai/chat#generative-ui).

Chats started from the bot use the bot's features. They cannot be changed in the chat settings.

Bot cards and the bot page show the bot's enabled features.

## Publish Readiness Rules

**Publish bot** stays disabled until:

- An AI behaviour block is linked
- The AI behaviour block is marked Ready
- Every linked repository block is marked Ready
- Every linked repository block has at least one attached asset

## Block Types

**Add behaviour** on the Behaviour tab and **Add repository** on the Repositories tab open `/app/hub/blocks/add`, where one of two types is chosen. `/app/hub/blocks/add?type=database` opens it on the repository type.

- AI behaviour (template block)
- Repository (database block)

A bot links one AI behaviour block and any number of repository blocks.

Each block can have:

- Draft or Ready publication status
- Metadata and versioning
- Visibility and grants
- Capability-based actions (edit, delete, manage access)

A block's page is `/app/hub/blocks/<block id>`. Its **More options** menu holds **Access & groups**, **Edit block** (`/app/hub/blocks/<block id>/edit`) and **Delete block**.

## Repository Blocks

A repository block's page lists its attached assets and its retrieval configuration:

- **Retrieval mode**: Dense, Sparse or Hybrid
- **References**: Minimum, Default and Maximum
- **Max per asset**, **Candidate limit** and **Score threshold**, under the advanced settings

Above the assets, **Jobs** opens the vectorisation job history for the repository. The **More options** menu next to it holds the vector store actions:

- **Create vector store** queues a vectorisation job for the repository's assets, after a confirmation.
- **View vector points** opens the indexed passages at `/app/hub/blocks/<block id>/points`.

## Repository Playground

Published repositories expose a playground where users can test retrieval queries directly against that repository. Open it with **Playground** on a repository under Repositories > Published; it lives at `/app/hub/repositories/<block id>/playground` and lets you choose the retrieval mode for each search.

This is useful for:

- Validating chunk quality
- Verifying retrieval mode behaviour
- Debugging missing or low-quality results before attaching to bots

## Sharing And Access

Bots, blocks and assets expose the same access dialog, **Access & groups**, for visibility, groups, and direct grants. The bot editor's sharing step embeds it.

A grant gives one of three resource roles:

- **Viewer** can find, use and read the resource. On a bot this is enough to chat with it.
- **Editor** can also edit the resource.
- **Manager** can also delete the resource and manage its access.

The person who creates a resource owns it and holds every action on it. Details, including how access passes from a bot to its blocks and assets, are in [Access Control](/docs/using-orcai/access-control).

For a full setup sequence from assets to a published bot, see [Workspace Setup For Admins](/docs/using-orcai/workspace-setup).
